# AnyGSLoc v4：证据收尾、叙事与图件设计

日期：2026-09-25。性质：写作计划与初步审计，不是新实验结果；本轮未修改冻结算法、未启动实验、未生成最终图。

## 最新决策：路线引出问题、完整算法计时、整套图件优先

本节依据用户进一步讨论更新，优先于下文原先“三张核心图优先、尾部计时正文展示”的建议。

### 叙事入口修正

“转换”是我们的解决方案，不是读者首先面临的问题。引言从 Gaussian 定位技术路线引入：以 STDLoc 为代表的方法把特征嵌入 Gaussian，通过基元关联的稀疏匹配与渲染式稠密细化完成定位；ULF-Loc 已转向直接融合地标特征，不能笼统把它也称作 alpha-blending 特征训练方法，但仍采用 Gaussian 地标和 coarse-to-fine 定位。

在承认已有精度收益后提出问题：**能否不依赖在线渲染和额外稠密细化，仍保留 Gaussian 定位的精度优势，并把部署表示缩减为紧凑的稀疏地图？** 然后才解释我们的选择：用跨视角观测重新定义定位地标，而非仅对既定渲染基元赋予更好的特征，再以互补约束选择地图。

“坐标/观测误差可能限制稀疏定位”是机制假说与消融支持的结论；“所有现有方法因为这个问题才必须细化”没有被证明，不能写。文献范围限定 Gaussian 定位的相关路线，不写成所有视觉定位方法均如此。

### 实时性口径核验

已核实 `anygsloc/online/runtime.py:58–133`：runtime_ms 从图像转入设备与 float 转换开始，包含有效域应用、SuperPoint、描述子处理、全局匹配、筛选、GPU→CPU 对应点传输、相机内参构造、PoseLib 完整调用。约 67.1 ms 是完整在线算法调用的平均耗时，不是仅匹配或仅位姿求解。

`tools/benchmark_release.py:39–47` 的 loop wall 还包括磁盘读图/解码、生成去畸变有效域、GT pose_error 和 Python 评测记录；它是离线评测循环吞吐，不应直接称为算法部署端到端 FPS。frame_io_geometry_pose_ms 不包含 GT 误差计算，但包含输入准备；两者也不同。

因此正文可以以“feature extraction + matching + pose estimation”的算法平均耗时为主要速度指标，排除磁盘 I/O、GT 评测和一次性初始化。说明输入是已准备的图像/有效域；必需的逐帧处理不能选择性排除。固定标定可预计算有效域，但当前代码逐次构造，尚未实施缓存，不把预期收益当实测。

不要求正文展示 P95、尾部图或 loop FPS；保留原始记录供审计即可。“平均实时定位”与“每帧都满足 deadline”不同，不声称后者。67.1 ms 的倒数约 14.9 Hz 是宏平均耗时换算值，不是另一次实测吞吐。跨方法仍需统一计时边界与说明分辨率/硬件。缺少最小资产统计与成本细节，不代表现有算法速度结果无效或缺少主步骤。

## 1. 总体决策

不增加方法复杂度。采用一个应用目标、两个技术障碍、两个主要设计、三类可测结果的叙事。

**应用目标：把已有 Gaussian 场景转换为能独立部署的紧凑稀疏地图，以简单在线链路获得有竞争力的定位精度。**

技术障碍一：渲染基元的身份、坐标与混合观测，不天然等于可重复匹配的定位地标。设计一是基于有效观测和跨视角对应重建地标的几何与描述子，而非把高斯中心直接当定位点。

技术障碍二：单点可靠不代表点集提供互补匹配和位姿约束。设计二是结合匹配覆盖与位姿信息的紧凑选择，不只是按质量取 Top-N。

因果链应分清：几何与描述子构建支持单阶段精度；选择支持地图压缩；不依赖在线渲染与额外稠密细化支持简化部署。不能把全系统加速归功于选择器。

推荐核心表述：

> AnyGSLoc separates the rendering representation from the localization representation: it uses Gaussian-derived multiview observations to reconstruct discrete landmarks, then retains a compact subset supporting complementary matching and pose constraints. The resulting map supports single-stage sparse localization without online scene rendering or an additional dense refinement stage.

不要写成既有方法理论错误、我们全局最优。多视角三角化、描述子融合、信息选择都有成熟背景；贡献应落在具体转换问题、组合设计和实证结果，不把标准公式包装为新理论。

## 2. 现有证据允许什么主张

| 主张 | 现有证据 | 写作边界 |
|---|---|---|
| 单阶段可接近两阶段精度 | Cambridge 本地复现，ours TE 8.871 cm；mask-off STDLoc/ULF-Loc fine 8.799/8.475 cm | 有竞争力而非全面精度最优；不同输入、地图和实现不构成纯单因素比较 |
| 不同坐标构造影响定位 | 共同点 ray/depth/center TE 8.765/9.911/11.667 cm | 不是所有场景获胜，也不是完整几何链路消融 |
| 观测处理整体有用 | 全关闭到全开启，compact TE 9.471→8.871 cm、R5 38.74→42.08% | 此处包含 completion；不能与 completion 固定开的 9.373 cm 行混淆；不能据此证明每个开关重要 |
| 可大幅压缩地图 | 五场景 535,840→176,329 点，减少 67.1%；TE 8.762→8.871 cm | 存在逐场景退化；不是无损压缩 |
| 在线核心较快 | 当前主线核心 mean 67.1 ms | 不是端到端稳定 10 Hz；v3 同系列 loop 宏平均 6.14 queries/s，mean scene P95 182.9 ms |
| 选择带来加速 | full/compact 核心 66.52/67.10 ms | 当前不支持平均加速结论 |
| 支持多种先验 | 优化式 2DGS/3DGS 结果接近 MAtCHA | 不支持任意质量不敏感；保留前馈式先验负结果及接入不确定性 |

本方法转换和在线阶段没有语义分割依赖；MAtCHA 上游语义准备应披露但分阶段计费。所有新 query 语义 mask 已关，不要把“不用 query 语义模型”当作相对于同样关闭该模型的基线的独占优势。共享特征网络仍需计算资源，不能写成无 GPU 依赖。

## 3. 先收尾实验表，而不是重新铺开实验

### 3.1 优先补 Table IX：部署成本

当前源文件有四个 TBD：两个基线的稀疏点数与部署地图大小；还有基线 P95 和 loop rate 的空项。

1. 清点各方法各阶段真正读取的资产：稀疏 XYZ/descriptor、Gaussian 场景、场景专属 detector/feature 权重；共享网络权重另列。fine 需要 Gaussian 时不得只算 sparse bank。coarse/fine 分行。
2. 现有 benchmark receipt 包含逐查询 timings，可在明确阶段边界后补基线 P50/P95，不必先重跑 GPU。
3. loop rate 不可直接取 receipt 总 wall-time 的倒数，后者可能包含初始化、warmup、准备。缺少统一完整循环记录时标 NR，必要时只补测计时，不改方法。
4. 并列硬件、分辨率、特征上限、预计算边界、读图/传输是否计时。当前实测速度不等于等分辨率算法速度比。
5. scene-equal mean、mean of scene P95 与 pooled P95 是不同统计量；不得混名。MB 明确十进制或 MiB。

离线成本分 supplied-prior conversion 与 from-images total 两种使用情境。后者才加 prior、可选语义准备和优化成本。基线联合训练不要人为拆成不存在的独立 RGB/feature 训练成本。缺失上游日志标 NR，不能补零，也不能从最终文件时间戳臆测训练时长。

### 3.2 核心消融与辅助结果

- 正文三个小面板：几何来源；观测联合及关键拆分；full/compact 与选择变体。沿用已有组合实验，不为“每行都正收益”调整算法或指标。
- 几何以 TE/RE、召回和尾部为主，报告共同点覆盖。现有 ray 使用原 Track 坐标，其他来源采用共同可用观测；若要强化严格几何隔离，可仅补同观测 ray 重拟合敏感性分析，明确这是新对照而非已完成结果。
- 观测把融合、V2、completion 拆解表移附录，正文保留联合结果和最有解释力的拆分。completion 写入实现但不独立声称贡献。
- 选择必须加入 N、地图字节，精度变化与成本一起看；已有不等点数选择变体不能伪装成相同预算对照。没有固定预算证据时只画已有真实操作点，不插出“实测 Pareto 曲线”。
- 24 场景主表、Cambridge coarse/fine、本地复现与 published 数字分开。不同 prior 保留完整附录。
- 不新增多 seed 大套实验。可以从已保存逐查询结果补 CDF、失败率、配对变化；区间如用配对 bootstrap，需要说明采样单元及序列相关性，不能包装为独立重复实验。

## 4. 图件设计：先机制，后美化

### Fig. 1 问题引入 / teaser

**问题：为什么有了高斯场景还需要重新构建定位地图？**

选同一真实场景的建筑边界或重复纹理局部：左为实际渲染和局部特征；中为对应高斯中心、深度反投影与多视角射线估计的空间关系；右为最终稀疏地图与真实 query 的定位结果。底部只列核验后的地图点数、单阶段误差和明确口径耗时。

中间可用简化示意解释“渲染支持不等于定位坐标”，但必须标 schematic，不可把示意误差当测量。不要用重建 RGB 漂亮程度代替定位证据。

### Fig. 2 方法总览：真实中间产物 + 少量运算符

上排 offline 占主要宽度：Gaussian 缩略图及已知相机 → 两三张渲染观测与筛选点 → 彩色 Track 连线和多射线几何 → 候选 XYZ/descriptor 图 → 全图/紧凑图叠加。

下排 online：一张真实 query → 稀疏 2D–3D 连线 → robust PnP → 相机位姿。部署分界只允许紧凑地图跨过，不把训练期统计也画成在线依赖。

每模块只保留短标题和一个核心操作。V2、融合、completion 放在对应构建模块内部，不让工程细节与两个主要设计平级。删掉当前总览中未经本轮实验验证的 captured RGB 虚线分支，或明确放到补充说明作为兼容能力。

### Fig. 3 几何机制（最高优先级）

**问题：重新估计地标坐标到底改了什么？**

同一组共同 Anchor ID 和描述子，三列 depth / center / ray。上排同一真实 query 的局部投影放大；中排相机与对应射线的 3D 局部侧视；下排五场景定位误差/CDF或逐查询配对变化。

## 5. 方法理论：少而必要，不是少而省略前提

主文围绕四个问题：什么证据能形成 Track？为何重建坐标？为何一份描述子足够部署？为何选择互补点集？

优先保留：核心观测/关联定义，固定相机鲁棒多射线目标，描述子融合定义，局部位姿敏感性关系，匹配容量与归一化信息增益，选择约束/停止准则。公式数量不硬凑，可从当前约二十余个编号压缩至约 8–10 个必要关系。

标准 alpha 合成介绍压成文字/一式；三角化正规方程、正定性推导、完整 Jacobian 和 matroid 背景移附录。污染率 Bayes 式仅靠假设坏样本通过率更低，不能证明 V2 有效，不作为核心理论。

位姿敏感性说明必须保留正确对应、局部线性化和非退化条件。log-det 说明互补信息的设计动机，不给未证明的真实 query 最优性、全局可观测保证或近似比。

两项投稿前核验：

1. **关联图退化检查**：统计观测/候选节点度数、共享邻居、实际增广路径和相对于简单计数的差异。如果真实图几乎一一对应，匹配理论需降调；不是预先认定代码错误。
2. **信息更新一致性**：已检查 `anygsloc/mapping/pose_evidence.py`：B 按 candidate/view 固定预计算，含该行集合的置信度与协方差。因此当前重分配未必要求重算 B，H+B 不是已确认 bug。应把固定贡献前提写清，并用小图测试核验增量矩阵与从头重建相同。

Algorithm 1 从流程标签改成真正可复现的决策步骤：输入/已知相机、可用原生缓冲区、Track冲突处理、候选资格、融合、选择 gain/约束/更新/停止、输出。one robust PnP 指一次求解器调用，不是无 RANSAC 迭代或无求解器内部优化。
